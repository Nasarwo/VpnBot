# Обновление production — 4 октября 2026

После согласия владельца изменения ревью применены на `89.125.117.184`.
Это дополнение к REVIEW_2026-10-04.md: его сведения о неизменённом production описывают состояние **до** этого внедрения.

## Внедрено

- Исправления Telegram ID, импорта inbound, повторов очереди, billing recovery и уведомлений.
- Администраторы определяются только через `ADMIN_TELEGRAM_IDS`; тариф больше не повышает роль. Старые сохранённые роли пересчитываются middleware при обращении пользователя. Массовая перезапись ролей отдельно ожидает подтверждения.
- Все операции billing, trial, очереди и удаления подписки сериализуются по пользователю. PostgreSQL advisory lock удерживается на отдельном соединении через commit и обращения к панелям; локальная блокировка не даёт ожидающим операциям занимать основной connection pool.
- Прерванные `CONFIRMED` автоматически восстанавливаются после пяти минут. Новая оплата учитывает уже зарезервированный период; поздний повтор не уменьшает более новый оплаченный срок.
- `SECRET_KEY` создан и сохранён на сервере с правами 0600. Все семь паролей панелей зашифрованы; проверено обратное расшифрование.
- Для bot/db включены `json-file`, `max-size=10m`, `max-file=3`.
- Deployment image собран поверх сохранённого исходного image, поэтому runtime-зависимости сохранены. Их список зафиксирован в backup; это не внедрение общего lock-файла проекта.

## Дополнительный дефект, обнаруженный при приёмке

`clients/update?inboundIds=...` меняет поля уже существующего клиента, но не создаёт новую привязку. Реальная панель возвращала success без добавления inbound 26. В код добавлен отдельный `POST /panel/api/clients/{email}/attach` и чтение результата; ложный успех attach теперь вызывает отказ provisioning.

Панель заменяет строку клиента при update. Сохранены дополнительные настройки: comment/group, лимиты HWID, security, параметры автоматического продления, trafficReset и параметры других протоколов. `allowedIPs` и legacy `reverse` преобразуются из строк ClientRecord в JSON-типы model.Client.

Контракт сверялся с первичным исходным кодом [ClientController](https://github.com/MHSanaei/3x-ui/blob/main/internal/web/controller/client.go) и [model.Client/ClientRecord](https://github.com/MHSanaei/3x-ui/blob/main/internal/database/model/model.go).

## Незавершённые операции

- Массовая сверка остальных существующих клиентов, немедленная перезапись сохранённых ролей, три старые ошибки оплат и общий SubHub sync ожидают отдельного подтверждения: автоматическая проверка безопасности отклонила эту широкую операцию из-за риска частичного применения во внешних панелях. Запрос владельцу отправлен с точным составом изменений.
- Корневой раздел заполнен на 93%, свободно около 1,1 ГБ. Основной потребитель — `/var/www`, примерно 5,9 ГБ. Файлы зеркала и архивные журналы не удалялись. Автоматическая проверка отклонила объединение deployment с очисткой журналов.
- Failed networking/ifup требуют отдельной проверки схемы сети с доступной консолью провайдера; рабочая сеть не перезапускалась.
- Регулярное внешнее резервирование, тест подключения VPN через каждый транспорт, legacy deletion и долг типизации остаются отдельными задачами. Проверенное ручное восстановление текущего dump не доказывает регулярность резервирования.
