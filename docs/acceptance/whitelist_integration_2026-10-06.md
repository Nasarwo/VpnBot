## Изменения

- Бот читает `/hosts/byInbound/{id}` при синхронизации whitelist XHTTP и проверяет
  единственный активный внешний Host с TLS, SNI, портом и проверкой сертификата.
- Оба приложения поддерживают API-токен через явное имя `@api-token` и поле пароля.
  Токен передаётся только по SSH между разрешёнными production-серверами.
  В боте хранится через `EncryptedString`; в SubHub — в защищённом конфиге.
  Вход обычных серверов по паролю сохранён. Схема БД не менялась.
- SubHub в явном режиме получает готовую ссылку из `/clients/links/{email}`.
  Поддерживается ровно один VLESS inbound и одна TLS/XHTTP-ссылка на клиента.
  Проверяются схема, UUID владельца, адрес, порт, SNI и запрет allowInsecure.
  Адрес, путь, Host и транспортные параметры не задаются в исходниках приложений.
- `include_clients` ограничивает выдачу пилотом. При первоначальном подключении
  список был пустым: существующий клиент whitelist-панели уже совпадал с подпиской
  SubHub и не должен был получить новый конфиг автоматически.
- Готовая ссылка сохраняется в ClientNode, как остальные секретные ссылки.
  В sanitized snapshot её секретное поле превращается в SHA256 fingerprint;
  поле NormalizedClient не попадает в repr.
- Happ получает отдельный ручной JSON-конфиг VLESS TLS/XHTTP. В автоматические
  профили этот сервер не входит. Дополнительные форматы для Clash/sing-box в этом
  этапе не реализованы и не проверены.

## Резервные копии и откат

- Бот: `/root/vpnbot-backups/20261006-whitelist-connect/`. Снимок PostgreSQL,
  три исходных модуля, исходный compose override и сохранённый образ.
  Новый образ `vpnbot-bot:whitelist-hosts-20261006` построен поверх фактически
  работающего образа, изменены только три модуля. Override указывает на этот образ;
  изменения также внесены в исходники на сервере для последующей сборки.
- SubHub: `/root/subhub-backups/20261006-whitelist-connect/`. Согласованная копия
  SQLite (`quick_check=ok`), конфигурация, environment и исходники приложения.

Порядок отката: сначала бот, затем SubHub. На боте:

```sh
/root/vpnbot-backups/20261006-whitelist-connect/rollback.sh
```

Скрипт отказывается работать после массового включения. Текущей версией удаляет
только синтетическую подписку с панелей, отключает whitelist-сервер, затем возвращает
старые исходники, override и образ. При ошибке удаления пилота откат прекращается.
Синтетический User/история корректировки остаются для аудита без активной подписки.

На SubHub:

```sh
/opt/subhub/.venv/bin/python /root/subhub-backups/20261006-whitelist-connect/rollback.py
```

Скрипт возвращает семь изменённых файлов и исходную конфигурацию, удаляет только
добавленные данные server_id `whitelist` из кеша SubHub, запускает сервис.
Снимки БД автоматически не восстанавливаются: операции реальных пользователей после
создания снимка должны сохраниться. Скрипты подготовлены; намеренный откат production
в этом этапе не выполнялся.

## Инциденты подготовки

Автоматическая проверка отклонила локальный экспорт учётных данных и последующую
передачу между серверами до явного согласия пользователя. После согласия выполнена
передача через память по SSH, без локальной копии и без вывода секретов.
Установочный логин панели устарел, поэтому использован уже действующий API-токен;
пароль администратора не менялся.

Первый служебный скрипт бота из `/tmp` импортировал установленную старую копию
пакета. Сервер был записан со статусом ошибки, но пользователи/квоты не создавались.
Импорт переключён на фактический `/app`, повторная синхронизация завершилась успешно.
Основной процесс бота использует `/app`.

Первый прогон выдачи показал наличие whitelist в URI, но его отсутствие в основном
JSON Happ: тот использует отдельный renderer. Renderer исправлен; повторная удалённая
проверка основного ответа прошла.
