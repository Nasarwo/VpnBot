# Приёмка на Android / Happ 4.6.0

Устройство и версия подтверждены пользователем 6 октября 2026 года.
Пользователь подтвердил работу обоих конфигов на устройстве в общей Wi-Fi сети.
Проверки исчерпания квоты, покупки, срока и переноса на телефоне ещё не выполнены.
Названия кнопок зависят от интерфейса
приложения; ниже указаны действия и ожидаемый результат.

## Условия начала

- Отдельная тестовая учётная запись, отдельные панели и SubHub, доступные с Android.
  Для согласованной общей Wi-Fi сети подготовлен отдельный HTTP-шлюз на
  `192.168.1.105:58580`; он отдаёт только GET `/connection/<token>`.
  Админские API остаются на loopback, LAN-запрос к `/admin/servers` возвращает 404.
  Прямые адреса `*.acc.test` и `127.0.0.1` с телефона не используются.
- Обычный конфиг и конфиг услуги находятся в одной подписке; оба доступны с
  устройства. Ссылка подписки и UUID не публикуются в отчёте.
- Для проверки блокировки квотой у тестовой записи заранее согласован небольшой
  баланс; изменения выполняются через учёт услуги, а не только через поле панели.
- Записаны исходные бесплатный и купленный остатки, срок и статус конфигов.
- Для проверки собственно обхода белых списков нужна мобильная сеть, на которой
  в данный момент действуют ограничения. Проверка на обычном Wi-Fi этого не докажет.

## Шаги

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Импортировать тестовую ссылку подписки в Happ, обновить её | Видны обычный конфиг и отдельный конфиг услуги; нет дублей |
| 2 | Подключить обычный конфиг, открыть заранее выбранный HTTPS-ресурс | Ресурс открывается; платный и бесплатный баланс услуги не расходуются |
| 3 | Переключиться на конфиг услуги, скачать файл известного размера | Соединение работает; после опроса панели и сверки бота растёт расход услуги; сначала уменьшается бесплатный остаток |
| 4 | Выполнить синтетическую покупку трафика на тестовом стенде, подтвердить администратором | Увеличивается только купленный остаток; срок и бесплатный остаток прежние; повтор подтверждения ничего не добавляет |
| 5 | Исчерпать небольшой тестовый бесплатный остаток и продолжить передачу | Далее уменьшается купленный остаток |
| 6 | Исчерпать весь тестовый баланс, обновить подписку, повторить подключение | Конфиг услуги больше не передаёт трафик; обычный конфиг работает при активной подписке. Уже сохранённый в Happ конфиг также заблокирован панелью |
| 7 | Начислить тестовый пакет, дождаться применения и обновить подписку | Конфиг услуги снова доступен и работает без смены ссылки подписки |
| 8 | Завершить срок тестовой подписки при положительном купленном остатке | После применения срока обе конфигурации не передают трафик; купленный остаток сохранён |
| 9 | Подтвердить тестовое продление | Срок обновлён; бесплатный остаток сброшен до 10 ГиБ, купленный сохранён; конфиги снова работают |
| 10 | Перенести тестового клиента на другой inbound через админ-функционал, обновить подписку в Happ | Ссылка подписки прежняя; появился актуальный конфиг, прежний доступ не работает после завершения переноса |
| 11 | Отключить Wi-Fi, повторить подключение услуги в сети с действующими белыми списками | Зафиксирован доступ к ресурсу, который без VPN недоступен. Успешное подключение в неограниченной сети не засчитывается как эта проверка |

Сначала проверяются шаги 1–3. После каждого изменения нужно дождаться подтверждения
применения в боте и синхронизации SubHub. При сбое записываются время с часовым
поясом, шаг, текст ошибки и обезличенный скриншот; секреты и ссылка подписки скрываются.

- Тестовые VLESS-порты: `192.168.1.105:52443` (услуга), `:52444` (обычный).
- Синтетические Telegram ID 740001/740002, отдельная БД `wlacc_happ`.
  Настоящий Telegram-транспорт не вызывается.
- Начальная выдача: 10 ГиБ бесплатно, 0 купленного; срок 30 дней. Проверочные
  загрузки стенда могут уменьшить бесплатный остаток перед проверкой телефона.
- Состояние и ссылка: `/tmp/vpnbot-happ-wifi-20261006/happ-ready.json` (0600),
  QR: `/tmp/vpnbot-happ-wifi-20261006/happ-qr.png`.
- Подготовка: `ops/acceptance/happ_wifi_prepare.py` после запуска `stack.sh`
  с префиксом `happacc`, портами API 52355/52356, PG 55441, SubHub 58184/58185.
  Подготовка требует свежего стенда, повторно на готовой записи не выполняется.

Первые действия на устройстве: подключиться к общей Wi-Fi сети, импортировать
тестовую ссылку/QR, обновить подписку, проверить наличие двух конфигов, затем
поочерёдно подключить каждый и открыть HTTPS-ресурс. Результаты фиксируются
после сообщения пользователя; локальная проверка через xray-клиент их не заменяет.

Стенд оставлен работающим для ручной проверки. После её завершения удалить
только контейнеры `happacc-gateway`, `happacc-pg`, `happacc-xui-wl`,
`happacc-xui-std`, `happacc-files`, `happacc-subhub`, `happacc-subhub-poll`
через `docker rm -fv`, затем сеть `happacc-net`. Состояние в `/tmp` временное.
