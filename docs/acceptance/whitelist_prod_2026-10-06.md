## Остановка systemd

Расширенная удалённая проверка выявила потерю 2 097 356 байт при `systemctl restart
x-ui`: панель сохранила 0 байт финальной порции. В журнале — отказ gRPC при финальном
чтении счётчиков (`connection reset by peer`). Сервис имел `KillMode=control-group`,
при котором SIGTERM одновременно получали панель и её дочерний Xray. Отдельный
перезапуск Xray через API проходил.

Добавлен `/etc/systemd/system/x-ui.service.d/20-final-flush-stop.conf`:

```ini
[Service]
KillMode=mixed
```

При штатной остановке SIGTERM получает основной процесс панели; он сохраняет расход
и останавливает ядро. По истечении прежнего таймаута 90 с systemd завершит оставшиеся
процессы группы SIGKILL. Скрипт отката удаляет этот новый drop-in и перечитывает unit.
Снимок отрицательного прогона:
`whitelist-prod-20261006/control-group-failure-result.json`.

После изменения только `KillMode` тот же сценарий прошёл: прирост расхода Xray
перед завершением панели — 2 097 356 байт, прирост панели после запуска —
2 097 356 байт. Это подтверждает причину отказа для проверенного сценария.

## Границы проверки

Проверка на синтетическом клиенте запускается непосредственно на сервере и
использует существующий inbound. Она не подтверждает доступ через мобильные белые
списки или работоспособность Happ через внешний адрес cc. Бот и SubHub в этой
операции не обновляются, услуга всем пользователям не включается.

Патч сохраняет трафик до последнего снимка. Передача между снимком и остановкой
ядра может потеряться; SIGKILL и отключение питания не покрыты.
