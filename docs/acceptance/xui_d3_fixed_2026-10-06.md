# Проверка исправленной 3x-ui — 6 октября 2026

Этот отчёт фиксирует проверенную ревизию базы счётчиков. Позднее патч расширен
финальным сохранением: `xui_final_flush_2026-10-06.md`. Успешные проверки ниже
не распространяются на новую ревизию. Проверенная версия сохранена в
`d3-fixed-20261006/verified-baseline.patch`, рецепт —
`d3-fixed-20261006/Dockerfile.verified-baseline`.

## Область проверки

Изолированная сборка и реальный VLESS/REALITY-трафик. Рабочие серверы,
production-панели и Telegram не использовались. Бот и SubHub не менялись.
Пользователь подтвердил работу обоих конфигов в Happ на Android 4.6.0 по Wi-Fi;
остальные сценарии на устройстве ещё не выполнены.

VpnBot: `520d65e230c91491efdd8733357836adefa410f6` (код `app/` совпадает с
предыдущей приёмкой). SubHub: `ff5dfd3dafff6eeb8a06b769485000173b56ff95`.
Python 3.12.14 и версии Python-зависимостей — те же, что в отчёте
`whitelist_repeat_2026-10-06.md`. Образы и тесты запускаются локально в Docker
Desktop; адреса API доступны только через loopback.

Сквозной сценарий подтвердил раздельные остатки, расход бесплатного первым,
покупку и повтор подтверждения, продление, trial, бессрочный доступ, истечение,

при `enable=true`, чтобы автоматическое отключение панелью не маскировало результат.

## Неуспешные промежуточные прогоны

Их протоколы сохранены, а не заменены итоговым успешным результатом:

1. `whitelist.json`: 89 OK / 1 FAIL — финальное ожидание SubHub завершилось
   таймаутом. Сверка учёта до него была успешной. Последующая отдельная
   синхронизация завершилась; точная причина одиночного таймаута не установлена.
2. `whitelist-repeat.json`: 89 OK / 1 FAIL — на повторно использованной панели
   уже оставался `LIFEACC0001` из предыдущего прогона, тогда как проверка привязки
   требовала отсутствия такого клиента. Сценарий создаёт новую БД бота, но не
   очищает все существующие клиенты панелей. На пересозданном чистом стенде
   проверка привязки и весь сценарий прошли.

## Ограничения учёта и отключения

1. Принудительная остановка Xray до следующего опроса всё ещё теряет накопленный
   хвост старого ядра. В первом варианте S7 нижняя граница потери — 3 931 813 Б;
   в окончательном варианте — **4 038 309 Б** (получено 14 113 760 Б,
   учтено 10 075 451 Б; остановка через 4,3 с после опроса с приростом).
   Патч базы не добавляет финальное сохранение счётчиков перед остановкой и не
   восстанавливает статистику после аварии. Плановые перезапуски требуют
   прекращения нового трафика и ожидания сверки; это не решает аварийную потерю.
2. Квота проверяется периодически, поэтому есть превышение между опросами.
   Патч не делает лимит точным до байта.
3. При `restartXrayOnClientDisable=false` удаление пользователя из ядра не
   оборвало уже открытый поток: в S6b были получены все 32 МиБ при квоте 4 МиБ.
   Для услуги нельзя отключать перезапуск при блокировке, рассчитывая на
   немедленную остановку текущих соединений.
4. База статистики меняется до записи дельт в БД панели — как и в upstream.
   Отказ записи БД и аварии панели между чтением и сохранением этим патчем не
   исправлены и отдельными fault-injection сценариями здесь не проверялись.
5. Проверка выполнена для одного процесса панели, локальной цели REALITY и
   AMD64. Установленные версии внешних серверов и действующие белые списки
   операторов этим стендом не проверяются.

## Как повторить

```bash
git clone --depth 1 --branch v3.9.0 https://github.com/MHSanaei/3x-ui.git /tmp/xui-d3
git -C /tmp/xui-d3 rev-parse HEAD
git -C /tmp/xui-d3 apply /mnt/ssd/DProjects/VpnBot/docs/acceptance/d3-fixed-20261006/verified-baseline.patch
DOCKER_CONTEXT=desktop-linux docker build \
  -f /mnt/ssd/DProjects/VpnBot/docs/acceptance/d3-fixed-20261006/Dockerfile.verified-baseline \
  -t wlacc-xui:d3-fixed-lock-20261006 /tmp/xui-d3
```

После сборки сценарий `xui_traffic_d3.py` запускается с `--image` этого образа.
Для нескольких независимых прогонов добавлены `--prefix` и `--port`;
API по-прежнему опубликован только на `127.0.0.1`.
Для бота используется **новая** папка состояния `stack.sh` и чистые контейнеры;
переменная `WLACC_XUI_IMAGE` выбирает тестовый образ. Нельзя переиспользовать
старый `panel.env`, в котором сохранён предыдущий образ.
